# Pi global agent reference

> **Reference copy** of `~/.pi/agent/AGENTS.md`.
>
> The canonical source lives on each developer's machine at
> `~/.pi/agent/AGENTS.md`. This vendored copy exists so new contributors can
> see what the global setup looks like before they have it.
>
> **Do not edit this file expecting changes to propagate.** Pi reads from
> `~/.pi/agent/AGENTS.md` only. Updates to the global setup are made on a
> machine that already has it, then mirrored here on the next standard bump.

## How to get this on your machine

In order of preference:

1. **Sync from another machine that already has it.** Use the `pi-agent-sync`
   skill — it copies `~/.pi/agent/` (skills, extensions, prompts, settings)
   over SSH from a primary machine to a new one. See
   `pi-agent-sync-docs/` if you have access, or run `/skill:pi-agent-sync`
   inside Pi.

2. **Manual copy.** Copy this file to `~/.pi/agent/AGENTS.md`:

   ```bash
   mkdir -p ~/.pi/agent
   curl -fsSL https://raw.githubusercontent.com/caesariodito/.standardization/main/templates/pi-agent/AGENTS.md \
     -o ~/.pi/agent/AGENTS.md
   ```

   You will not get the bundled skills (Matt Pocock, Karpathy guardrails as
   a callable skill, etc.) this way — only the routing rules. Install the
   skills separately if you want `/skill:grill-with-docs` and friends to
   resolve.

3. **Skip Pi global setup.** The repo-level `AGENTS.md` works standalone.
   You lose skills routing and the Karpathy guardrails as a callable skill,
   but the operating principles in Section 1 of the repo template restate
   the essentials inline. Coding agents will still behave reasonably.
